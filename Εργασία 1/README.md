# Εργασία 1 — Θέμα Β: Mini e-shop

Εφαρμογή μίας σελίδας (Single Page) για τη διαχείριση των προϊόντων ενός μικρού ηλεκτρονικού
καταστήματος (CRUD), μαζί με φόρμα εγγραφής πελάτη με live validation. Είναι γραμμένη μόνο με
**HTML, CSS και JavaScript**, χωρίς frameworks. Επιλέξαμε το Θέμα Β επειδή η Εργασία 2 είναι
επέκτασή του (βλ. «Προς την Εργασία 2» πιο κάτω).

## Εκτέλεση

Δεν χρειάζεται εγκατάσταση ούτε server. Ανοίγετε το `index.html` σε Chrome, Firefox ή Edge.

Στην πρώτη επίσκεψη ο κατάλογος γεμίζει με 12 ενδεικτικά προϊόντα, για να φαίνονται αμέσως η
ταξινόμηση, το φίλτρο και η σελιδοποίηση. Για να ξεκινήσετε από την αρχή: F12 → Application →
Local Storage → διαγραφή του κλειδιού `products` → ανανέωση.

## Τι κάνει

**Προϊόντα (κλειδί `products`)**

- Φόρμα προσθήκης και επεξεργασίας με πεδία *όνομα*, *κατηγορία*, *τιμή* και *διαθεσιμότητα*,
  και live validation σε κάθε πεδίο («Έγκυρο» ή μήνυμα λάθους):
  - το όνομα είναι υποχρεωτικό, 2–80 χαρακτήρες, και **μοναδικό** (χωρίς διάκριση πεζών/τόνων·
    το «οθονη 27"» θεωρείται ίδιο με το «Οθόνη 27"»)·
  - η κατηγορία επιλέγεται από λίστα·
  - η τιμή είναι θετικός αριθμός, έως 99.999,99 €, με έως δύο δεκαδικά.
- Πίνακας προϊόντων με κουμπιά «Επεξεργασία» και «Διαγραφή» σε κάθε γραμμή. Πριν από τη
  διαγραφή ζητείται επιβεβαίωση σε παράθυρο διαλόγου.
- Ταξινόμηση με κλικ στις στήλες *Όνομα*, *Κατηγορία* και *Τιμή* (πρώτο κλικ αύξουσα, δεύτερο
  φθίνουσα, με βελάκι ▲/▼).
- Αναζήτηση στο όνομα που φιλτράρει καθώς πληκτρολογείτε (αγνοεί τόνους και πεζά/κεφαλαία:
  το «βιβλιο» βρίσκει το «Βιβλίο»), φίλτρο κατηγορίας, και μήνυμα «Δεν βρέθηκαν προϊόντα» όταν
  δεν υπάρχει αποτέλεσμα.

**Εγγραφή πελάτη (κλειδί `users`)**

Η φόρμα της εκφώνησης, ως φόρμα εγγραφής πελάτη: Όνομα, Επώνυμο, Email, Ρόλος (Admin/User),
Ημερομηνία εγγραφής (προσυμπληρωμένη με τη σημερινή), Password και Επιβεβαίωση password.

- Όνομα / Επώνυμο: κεφαλαία ελληνικά χωρίς τόνους, με κενό ή παύλα για σύνθετα ονόματα
  (`ΓΕΩΡΓΙΟΣ`, `ΑΝΝΑ-ΜΑΡΙΑ` έγκυρα· `Γεώργιος`, `ΓΙΏΡΓΟΣ`, `GEORGE` μη έγκυρα).
- Email: έγκυρη μορφή και μοναδικό (χωρίς διάκριση κεφαλαίων).
- Password: τουλάχιστον 8 χαρακτήρες, ένα γράμμα, ένας αριθμός και ένα από τα `!@#$%^&*`, με
  ένδειξη ✔ / ✘ για κάθε κανόνα που ενημερώνεται σε κάθε πλήκτρο.
- Η επιβεβαίωση ελέγχεται ξανά όταν αλλάζει το password.
- Κάτω από τη φόρμα φαίνεται η λίστα των εγγεγραμμένων πελατών.

| Αρχείο | Περιεχόμενο |

## Σχεδιασμός κώδικα

### Κλάσεις και αποθήκευση

```
LocalStorageStore            κοινή λογική: load / save / all / findById / add / update / remove / restore
 ├── ProductStore            κλειδί "products"  + hasName(), search()
 └── UserStore               κλειδί "users"     + hasEmail()
Product, User                μία εγγραφή, με toJSON() για την αποθήκευση
```

- Οι εγγραφές ζουν σε πίνακα JavaScript (`store.items`). Το `load()` τον διαβάζει με
  `JSON.parse` όταν ανοίγει η σελίδα και το `save()` τον γράφει με `JSON.stringify`.
- **Κάθε** `add`, `update`, `remove` και `restore` καλεί αμέσως `save()`. Το UI δεν αγγίζει
  ποτέ απευθείας το `localStorage`, άρα ο πίνακας στη μνήμη και το αποθηκευμένο JSON δεν
  μπορούν να διαφέρουν.
- Το `ProductStore` και το `UserStore` κληρονομούν τη λογική αποθήκευσης από το
  `LocalStorageStore` και προσθέτουν μόνο ό,τι αφορά το δικό τους είδος (μοναδικό όνομα,
  μοναδικό email, αναζήτηση). Έτσι η αποθήκευση γράφεται μία φορά.
- Το `ProductStore.search({ text, category, sortKey, direction })` κάνει φίλτρο και
  ταξινόμηση σε ένα βήμα. Η σελιδοποίηση εφαρμόζεται μετά, οπότε τα τέσσερα συνεργάζονται σωστά.
- Αν το JSON στο `localStorage` είναι χαλασμένο, η λίστα ξεκινά κενή αντί να «σπάσει» η σελίδα.
  Αν το κλειδί `products` δεν υπάρχει (πρώτη επίσκεψη), μπαίνουν τα ενδεικτικά προϊόντα. Μια
  κενή λίστα `[]` μένει κενή.
- Αλλαγές από άλλη καρτέλα του browser εμφανίζονται αμέσως (γεγονός `storage`).

**Έλεγχος:** F12 → Application → Local Storage → η σελίδα → κλειδιά `products` και `users`.
Προσθέστε ένα προϊόν, ανανεώστε τη σελίδα, και το προϊόν είναι ακόμη στον πίνακα.

### Validation: HTML γνωρίσματα και Constraint Validation API

Οι φόρμες έχουν `novalidate`, ώστε ο browser να μη δείχνει τα δικά του αγγλικά μπαλονάκια.
Οι κανόνες όμως ελέγχονται σε δύο επίπεδα, για κάθε πεδίο (κλάση `FormController`):

1. **HTML γνωρίσματα**: `required`, `minlength`/`maxlength`, `pattern` (Όνομα/Επώνυμο),
   `type="email"`, `min`/`max`/`step` (τιμή). Τα ελέγχει ο ίδιος ο browser.
2. **Δικός μας κανόνας** για ό,τι δεν γράφεται σε HTML: μοναδικό email ή όνομα προϊόντος,
   σύνθεση password, ταύτιση επιβεβαίωσης. Ο κανόνας επιστρέφει μήνυμα και το δίνουμε στον
   browser με `setCustomValidity(μήνυμα)` (ή `''` όταν είναι έγκυρο).

Το τελικό «έγκυρο ή όχι» το δίνει το `checkValidity()`, που λαμβάνει υπόψη και τα δύο. Αν
αποτύχει γνώρισμα HTML και όχι ο δικός μας κανόνας, το μήνυμα προκύπτει από το αντικείμενο
`validity` (`valueMissing`, `patternMismatch`, `rangeUnderflow` κ.λπ.) στη `nativeErrorMessage()`.

- Ο έλεγχος τρέχει στο `input` (σε κάθε πλήκτρο) και στο `blur`. Το μήνυμα εμφανίζεται μόνο σε
  πεδία που ο χρήστης έχει ήδη αγγίξει, για να μη γεμίζει η φόρμα κόκκινα πριν γράψει κάτι.
- Στο submit ελέγχονται όλα τα πεδία και η εστίαση πηγαίνει στο πρώτο λάθος.
- Οι κανόνες (ενότητα 3 του `logic.js`) είναι **καθαρές συναρτήσεις χωρίς DOM**. Τους καλούν
  και οι φόρμες και η εισαγωγή JSON, άρα το αρχείο ελέγχεται με ακριβώς τους ίδιους κανόνες.

**Κανόνας ονόματος.** `GREEK_NAME_PATTERN = /^[Α-Ω]+([ \-][Α-Ω]+)*$/u` και το ίδιο κείμενο στο
γνώρισμα `pattern`. Το εύρος `Α-Ω` (U+0391–U+03A9) δεν περιέχει τα `Ά Έ Ή Ί Ό Ύ Ώ`
(U+0386–U+038F) ούτε τα `Ϊ Ϋ` (U+03AA–U+03AB), οπότε οι τόνοι και τα διαλυτικά αποκλείονται
χωρίς επιπλέον κώδικα. Το `([ \-][Α-Ω]+)*` επιτρέπει ένα κενό ή μία παύλα **ανάμεσα** σε λέξεις
(όχι στην αρχή ή στο τέλος, ούτε δύο συνεχόμενα).

**Password.** Οι τέσσερις κανόνες είναι ένας πίνακας (`PASSWORD_RULES`) που τον χρησιμοποιούν
και ο έλεγχος και οι ενδείξεις ✔ / ✘, οπότε δεν μπορεί να διαφωνούν.

### Εμφάνιση και ασφάλεια

- Το `render` αλλάζει μόνο το `tbody` του πίνακα. Η φόρμα και τα φίλτρα δεν ξαναφτιάχνονται,
  άρα δεν χάνεται η εστίαση ενώ πληκτρολογείτε.
- Κάθε τιμή περνά από `escapeHtml()` πριν μπει σε `innerHTML`: ένα προϊόν με όνομα
  `<img onerror=…>` εμφανίζεται ως κείμενο και δεν εκτελείται.
- Τα κουμπιά του πίνακα χειρίζονται από **έναν** listener στο `tbody` (event delegation),
  αφού οι γραμμές ξαναδημιουργούνται σε κάθε render.
- Οι τιμές εμφανίζονται με `Intl.NumberFormat('el-GR')` (π.χ. `1.234,50 €`) και οι
  συγκρίσεις κειμένου γίνονται με `localeCompare(…, 'el')`.
- Responsive: σε κινητό κάθε γραμμή του πίνακα γίνεται κάρτα (με τον τίτλο της στήλης από το
  `data-label`) και οι επικεφαλίδες ταξινόμησης γίνονται κουμπιά. Η σελίδα δεν κυλά οριζόντια
  ούτε στα 360px.
- Προσβασιμότητα: κάθε πεδίο έχει `label`, τα μηνύματα συνδέονται με `aria-describedby`,
  οι επικεφαλίδες έχουν `aria-sort` και στο παράθυρο επιβεβαίωσης η εστίαση μένει στα δύο
  κουμπιά του (Esc = Άκυρο).

## Bonus που υλοποιήθηκαν

1. **Εξαγωγή και εισαγωγή.** «Εξαγωγή JSON» και «Εξαγωγή CSV» (με BOM, για να ανοίγει
   σωστά με ελληνικά στο Excel). Η «Εισαγωγή JSON» ελέγχει **κάθε** εγγραφή με τους ίδιους
   κανόνες της φόρμας (`validateProduct`), απορρίπτει διπλότυπα ονόματα (και έναντι των
   υπαρχόντων και μέσα στο ίδιο αρχείο) και δείχνει αναφορά: πόσα μπήκαν και γιατί
   απορρίφθηκε καθένα από τα υπόλοιπα.
2. **Σελιδοποίηση.** 10 προϊόντα ανά σελίδα. Εφαρμόζεται μετά την αναζήτηση, το φίλτρο και την
   ταξινόμηση, και κάθε αλλαγή φίλτρου γυρνά στη σελίδα 1. Μετά από προσθήκη ή επεξεργασία, ο
   πίνακας πηγαίνει στη σελίδα όπου βρίσκεται το προϊόν και το επισημαίνει.
3. **Αναίρεση διαγραφής.** Μετά τη διαγραφή εμφανίζεται μήνυμα με κουμπί «Αναίρεση» για 6
   δευτερόλεπτα. Το `ProductStore.restore()` ξαναβάζει το προϊόν **στην αρχική του θέση**
   (όχι στο τέλος).

## Προς την Εργασία 2

Η εφαρμογή γράφτηκε ώστε να μεταφερθεί στην Εργασία 2 (React + Express + MongoDB):

| Εργασία 1 | Εργασία 2 |
|---|---|
| κλάση `Product` (name, category, price, available) | σχήμα Mongoose `Product`, ίδια πεδία |
| κλάση `User`, κλειδί `users` | σχήμα `User` (ο κωδικός γίνεται hash με bcrypt) |
| `ProductStore.search({ text, category, sortKey })` | `GET /api/products?search=&category=&sort=` |
| `add` / `update` / `remove` | `POST` / `PUT` / `DELETE /api/products/:id` (μόνο Admin) |
| κανόνες της ενότητας 3 (`validateGreekName`, `validatePassword`, …) | `validators.js` σε client και server |
| `SAMPLE_PRODUCTS` / «Εξαγωγή JSON» | `server/data/products.json` → `npm run seed` |
| μεταβλητές χρωμάτων στο `:root` | ίδιες μεταβλητές στο `client/src/styles.css` |

Ένα αρχείο από την «Εξαγωγή JSON» φορτώνεται απευθείας στη MongoDB με
`npm run seed -- <διαδρομή>/products.json` στον φάκελο `server/` της Εργασίας 2.

## Σημειώσεις

- **Οι κωδικοί των πελατών αποθηκεύονται στο `localStorage` σε απλό κείμενο.** Σε πραγματική
  εφαρμογή αυτό δεν γίνεται ποτέ. Εδώ επιτρέπεται μόνο για εξάσκηση, όπως λέει η εκφώνηση. Στην
  Εργασία 2 οι κωδικοί αποθηκεύονται στον server ως hash με bcrypt.
- Οι ημερομηνίες αποθηκεύονται ως `YYYY-MM-DD` (ταξινομούνται σωστά ως κείμενο) και
  εμφανίζονται ως `ΗΗ/ΜΜ/ΕΕΕΕ`.
- Το `localStorage` είναι ανά browser και ανά τοποθεσία του αρχείου: αν ανοίξετε το
  `index.html` από άλλο φάκελο, θα δείτε ξανά τα αρχικά προϊόντα.
