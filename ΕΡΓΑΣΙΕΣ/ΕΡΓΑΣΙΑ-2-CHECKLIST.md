# ΕΡΓΑΣΙΑ 2 — Checklist αποδοχής (βάση βαθμολογίας)

Ώρες για 1 άτομο. Με 2 άτομα: μοιράζεσαι server/client, αλλά η ευθύνη παραμένει 1-1.
Πριν από τον κώδικα: κλείστε τα **contracts** (endpoints, JSON, roles) μαζί, 2 ώρες. Μόνο έτσι δεν κολλάτε στο 60%.

## 0. Contracts (πρώτα αυτά, μαζί)

- [ ] Λίστα endpoints με request/response examples
- [ ] Σχήματα Mongoose (fields, required, unique, indexes)
- [ ] Roles matrix: τι επιτρέπεται σε User / Admin / guest
- [ ] Interface του `client/api.js` (τι functions εκθέτει) — μία πηγή αλήθειας για το client

## 1. Βάση δεδομένση (10%)

- [ ] Collections `users`, `products`, `orders` με Mongoose schemas
- [ ] `users`: required πεδία, **unique email**, hashed password (ποτέ plaintext)
- [ ] `products`: όνομα, κατηγορία, τιμή, διαθεσιμότητα (+ τουλάχιστον 1-2 extra fields)
- [ ] `orders`: χρήστης, ημερομηνία, σύνολο, **items snapshot** (όνομα, τιμή, ποσότητα)
- [ ] Script αρχικοποίησης `npm run seed`: **≥10 προϊόντα**, **1 Admin**, **1 User** (με γνωστά credentials για το README)
- [ ] Το seed να είναι idempotent (να μη δημιουργεί duplicates αν τρέξει δύο φορές)

## 2. Κατάλογος προϊόντων (10%)

- [ ] Τα προϊόντα φορτώνονται από τον server: `GET /api/products`
- [ ] Αναζήτηση βάσει ονόματος
- [ ] Φίλτρο κατηγορίας
- [ ] Ταξινόμηση βάσει τιμής (αύξουσα/φθίνουσα)
- [ ] (Επιτρεπόμενο) τα παραπάνω να γίνονται στη React — αλλά τα δεδομένα έρχονται από το server

## 3. Καλάθι & παραγγελία (15%)

- [ ] Προσθήκη/αφαίρεση προϊόντων, αλλαγή ποσότητας, υπολογισμός συνόλου
- [ ] Το καλάθι **διατηρείται μετά από ανανέωση** (localStorage)
- [ ] Στο checkout ο client στέλνει **μόνο** ids προϊόντων + ποσότητες
- [ ] **Ο server βρίσκει τις τιμές στη βάση**, υπολογίζει το σύνολο και αποθηκεύει την παραγγελία
- [ ] Ο server **δεν επιστρέφει/δεν δέχεται** τιμές από τον client (ούτε και τιμή ολόκληρης παραγγελίας)
- [ ] Κενή παραγγελία ή μη υπάρχον προϊόν → 400 με JSON message
- [ ] Ο User βλέπει το ιστορικό **μόνο των δικών του** παραγγελιών

## 4. Εγγραφή & σύνδεση (15%)

- [ ] Register / Login / Logout
- [ ] Οι κανόνες της φόρμας είναι **ίδιοι με την Εργασία 1** (κεφαλαία ελληνικά χωρίς τόνους, password rules, confirm)
- [ ] Passwords αποθηκεύονται ως **bcrypt hash** (cost ≥ 10), **ποτέ** σε plaintext
- [ ] Το API **δεν επιστρέφει ποτέ** password/hash σε responses
- [ ] Login επιστρέφει **JWT**, ο client το στέλνει σε κάθε επόμενο αίτημα στο `Authorization: Bearer <token>`
- [ ] Duplicate email → 400/409 με μήνυμα (όχι crash)
- [ ] Λάθος credentials → 401 με JSON message
- [ ] Logout: το token δεν περνά πλέον (ή μαθαίνεις από τον client να το αγνοεί — αλλά εξήγησε την επιλογή σου)

## 5. Ρόλοι / Authorization (15%)

- [ ] **User**: βλέπει κατάλογο, καλάθι, κάνει παραγγελίες, βλέπει μόνο τις δικές του
- [ ] **Admin**: προσθέτει/επεξεργάζεται/διαγράφει προϊόντα
- [ ] Ο έλεγχος γίνεται **στο server** με Express middleware
- [ ] Αίτημα χωρίς σύνδεση → **401**
- [ ] Αίτημα χωρίς δικαίωμα (User που θέλει να διαγράψει προϊόν) → **403**
- [ ] Το κρύψιμο κουμπιών στη React **δεν** αρκεί — το endpoint πρέπει να απορρίπτει

## 6. Validation & ασφάλεια (10%)

- [ ] Έλεγχος δεδομένων **και στον client και στον server**
- [ ] Μη έγκυρα δεδομένα (αρνητική ποσότητα, κενό όνομα, κακή τιμή) → **400** + JSON μήνυμα
- [ ] Τα secrets (σύνδεση DB, JWT key) στο `.env`
- [ ] `.env` **δεν** παραδίδεται · παραδίδεται μόνο `.env.example` (με τα ίδια κλειδιά, κενές τιμές)
- [ ] Καμία hard-coded secret μέσα στον κώδικα

## 7. REST API (10%)

- [ ] Σωστά HTTP methods: GET, POST, PUT, DELETE
- [ ] Σωστά status codes: 200, 201, 400, 401, 403, 404
- [ ] 201 σε δημιουργία, 404 σε ανύπαρκτο resource, 400 σε κακά δεδομένα
- [ ] Όλα τα endpoints επιστρέφουν JSON (όχι HTML/κενό)
- [ ] Ενδεικτικά endpoints (υποχρεωτικά να υπάρχουν, ονόματα ελεύθερα):
  - `POST /api/auth/register`, `POST /api/auth/login`
  - `GET /api/products`
  - `POST /api/products`, `PUT /api/products/:id`, `DELETE /api/products/:id` (Admin)
  - `GET /api/orders`, `POST /api/orders`

## 8. Εφαρμογή React (10%)

- [ ] Components: `ProductCard`, `Navbar`, `Cart` (ή ισοδύναμα)
- [ ] Σελίδες: κατάλογος, καλάθι, σύνδεση/εγγραφή, «οι παραγγελίες μου», διαχείριση προϊόντων (Admin)
- [ ] `useState` και `useEffect` χρησιμοποιημένα σωστά (όχι state για derived data, όχι effect χωρίς cleanup/dependencies)
- [ ] Όλες οι κλήσεις API **συγκεντρωμένες** σε `api.js` (καμία `fetch` spattered στα components)
- [ ] Σαφή μηνύματα επιτυχίας/λάθους για τον χρήστη
- [ ] Loading states (μηνύματα όσο περιμένει) και άδειες καταστάσεις
- [ ] Token στο client: `localStorage` (ή sessionStorage) — επιλογή που εξηγείς

## 9. Παραδοτέα

- [ ] `client/` και `server/` (χωρίς `node_modules`, χωρίς `.env`)
- [ ] `README`: στοιχεία ομάδας, βήματα εκτέλεσης (`npm install`, ρύθμιση `.env`, `npm run seed`, `npm run dev`), **λογαριασμοί δοκιμής (Admin/User)**
- [ ] `screenshots.pdf` με λεζάντα: κατάλογος, καλάθι, παραγγελία, σύνδεση, διαχείριση προϊόντων
- [ ] **Πίνακας δοκιμών** ≥5 περιπτώσεις με αποτέλεσμα (πρέπει να περιλαμβάνει τις ενδεικτικές):
  1. λάθος κωδικός (401)
  2. duplicate email (400)
  3. User που προσπαθεί να διαγράψει προϊόν (403)
  4. αρνητική ποσότητα (400)
  5. τροποποιημένη τιμή από τον client → ο server αγνοεί/απορρίπτει την τιμή και υπολογίζει τη σωστή
- [ ] zip `p3xxxxxx-p3yyyyyy.zip`

## Bonus (έως +10%, κάθε ένα +5%)

- [ ] **Αξιολογήσεις προϊόντων**: ο User βαθμολογεί 1–5 και σχολιάζει, ο μέσος όρος εμφανίζεται στον κατάλογο
- [ ] **Κατάσταση παραγγελίας**: ο Admin βλέπει όλες τις παραγγελίες και αλλάζει την κατάσταση (π.χ. «Σε επεξεργασία → Απεστάλη»), ο User βλέπει την ενημερωμένη κατάσταση
- [ ] **Σελιδοποίηση στον server**: `GET /api/products?page=2` με buttons στη React

## Checklist προφορικής (1 μέρα πριν)

- [ ] Εξηγώ πώς περνά το token από login → client → `Authorization` header → middleware
- [ ] Εξηγώ τη διαφορά 401 / 403 / 400 με δικό μου παράδειγμα
- [ ] Εξηγώ γιατί ο server υπολογίζει το total και τι γίνεται αν ο client στείλει ψευτική τιμή
- [ ] Εξηγώ τι κάνει το `npm run seed` και πώς δεν δημιουργεί duplicates
- [ ] Εξηγώ τι αλλάζει αν ο token λήξει ή αν ο χρήστης κάνει logout (και τι γίνεται με το token στο localStorage)
- [ ] Ξέρω τι κάνω αν ο MongoDB δεν τρέχει (error handling στο connection)
- [ ] Ξέρω ποιο είναι το μοναδικό γνώρισμα του bcrypt και γιατί δεν αποθηκεύω ποτέ plaintext
