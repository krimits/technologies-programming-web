# ΕΡΓΑΣΙΑ 1 — Checklist αποδοχής (βάση βαθμολογίας)

Κάθε item έχει «Definition of Done»: αν δεν το μπορείς να δείξεις/εξηγήσεις στο DevTools, δεν το θεωρείς τελειωμένο.
Ώρες: οι εκτιμήσεις είναι για 1 άτομο. Με 2 άτομα μοιράζονται, αλλά η ευθύνη παραμένει 1-1.

## Επιλογή θέματος (αποφασίζεις πριν αρχίσεις!)

- [ ] **Θέμα Α — Διαχείριση χρηστών** (ή Θέμα Β — Mini e-shop)
- [ ] Αν σκοπεύεσαι να κάνεις και την Εργασία 2 → **Θέμα Β** (η Ε2 είναι επέκτασή του).
- [ ] Θέμα Β επιπλέον: πίνακας προϊόντων (όνομα, κατηγορία, τιμή, διαθεσιμότητα) + sort/search/filter κατηγορίας + κλάσεις `Product`/`ProductStore` + key `products` (η φόρμα παραμένει «εγγραφή πελάτη»).

## 1. Φόρμα εισαγωγής χρήστη (πεδία)

- [ ] Όνομα, Επώνυμο, Email, Ρόλος (Admin/User), Ημερομηνία εγγραφής, Password, Επιβεβαίωση password
- [ ] Όλα τα πεδία υποχρεωτικά (`required`)
- [ ] Ημερομηνία εγγραφής προσυμπληρώνεται αυτόματα με τη σημερινή ημερομηνία (readonly)
- [ ] Ο Ρόλος είναι επιλογή (select/radio) — όχι free text

## 2. Live validation (20%)

- [ ] Σε κάθε παίξιμο (όχι μόνο στο submit) εμφανίζεται ανά πεδίο «Έγκυρο» ή μήνυμα λάθους
- [ ] Email: έγκυρη μορφή **και** μοναδικό (όχι διπλότυπα) — ο έλεγχος γίνεται στο σύνολο των χρηστών, όχι μόνο στη φόρμα
- [ ] Όνομα/Επώνυμο: **κεφαλαία ελληνικά χωρίς τόνους**· επιτρέπεται κενό ή παύλα για σύνθετα ονόματα
  - [ ] Έγκυρα: `ΓΕΩΡΓΙΟΣ`, `ΑΝΝΑ-ΜΑΡΙΑ`
  - [ ] Μη έγκυρα: `Γεώργιος` (πεζά), `ΓΙΏΡΓΟΣ` (τόνος), `GEORGE` (λατινικά)
  - [ ] Προσοχή στο Unicode: το `[Α-Ω]` πρέπει να αποκλείει σωστά τα `Ά Έ Ή Ί Ό Ύ Ώ` (U+0386–U+038F) και `Ϊ Ϋ` (U+03AA/AB)
- [ ] Password: ≥8 χαρακτήρες + ≥1 αριθμός + ≥1 γράμμα + ≥1 από `!@#$%^&*`
  - [ ] Έγκυρο: `123A$6789` · Μη έγκυρα: `Abcdefg1` (λείπει σύμβολο), `12345678$` (λείπει γράμμα), `Ab1$` (πολύ σύντομο)
- [ ] Επιβεβαίωση password ταιριάζει με το password
- [ ] Χρησιμοποιείται **και** HTML γνωρίσματα (`required`, `minlength`, `pattern`) **και** Constraint Validation API (`setCustomValidity`, `checkValidity`)
- [ ] Δίπλα στο password: ένδειξη `✔`/`✘` **για κάθε κανόνα** πολυπλοκότητας (μήκος / ψηφίο / γράμμα / σύμβολο)

> Το μυστικό: τα `pattern` του browser δεν καλύπτουν όλα (ελληνικά, μοναδικότητα email, confirm) →
> κράτα ένα δικό σου validator και χρησιμοποίησε `setCustomValidity` για να εμφανίσεις το δικό σου μήνυμα.

## 3. Πίνακας χρηστών (CRUD 20%)

- [ ] Εμφάνιση όλων των χρηστών
- [ ] Edit ανά γραμμή (τροποποίηση υπάρχοντος χρήστη, όχι δημιουργία νέου)
- [ ] Delete ανά γραμμή με **επιβεβαίωση** πριν τη διαγραφή

## 4. Ταξινόμηση (10%)

- [ ] Στήλες: όνομα, email, ημερομηνία
- [ ] Αύξουσα + φθίνουσα, με εναλλαγή (toggle) ανά κλικ στην επικεφαλίδα

## 5. Αναζήτηση & φίλτρο (10%)

- [ ] Πεδίο αναζήτησης: λέξη-κλειδί σε **όνομα, επώνυμο ή email**, φιλτράρει **καθώς πληκτρολογείται**
- [ ] Φίλτρο ρόλου: Όλοι / Admin / User
- [ ] Μήνυμα «Δεν βρέθηκαν χρήστες» όταν το αποτέλεσμα είναι κενό
- [ ] (Ναι) Οι search/filter/sort αλληλεπιδρούν σωστά μεταξύ τους

## 6. Δομή κώδικα & αποθήκευση (10%)

- [ ] Κλάση `User` (ιδιότητα ενός χρήστη)
- [ ] Ξεχωριστή κλάση `UserStore` με: add, find/search, update, delete
- [ ] Οι χρήστες ζουν σε πίνακα JavaScript
- [ ] Αποθήκευση στο `localStorage` στο κλειδί **`users`** με `JSON.stringify`
- [ ] Φόρτωση με `JSON.parse` κατά το άνοιγμα της σελίδας
- [ ] Η αποθήκευση ενημερώνεται **μετά από κάθε** add/edit/delete
- [ ] Έλεγχος: DevTools → Application → Local Storage → η σελίδα σου → `users` → προσθέτεις χρήστη, ανανεώνεις, ο χρήστης παραμένει
- [ ] Σχόλια στον κώδικα (ιδίως στα «μη προφανή» σημεία: validation, storage keys)
- [ ] Σημείωση στο README: στην πραγματική εφαρμογή οι κωδικοί δεν αποθηκεύονται ποτέ στον browser

## 7. Εμφάνιση / UX (10% + 5%)

- [ ] Σημασιολογικά HTML5: `header`, `main`, `section`, `form`, `table`, `footer`
- [ ] Σωστά `label` για **όλα** τα πεδία (click → focus στο input)
- [ ] Responsive: σε κινητό η σελίδα παραμένει χρηστική, **χωρίς οριζόντια κύλιση ολόκληρης σελίδας** (δοκίμασε ~360px)
- [ ] Μηνύματα επιτυχίας/λάθους, κενή κατάσταση, disabled states
- [ ] Οπτική συνοχή (spacing, colors, fonts), όχι «default HTML»

## Bonus (έως +10%, κάθε ένα +5%)

- [ ] **Export/Import**: κουμπί download σε CSV **ή** JSON + φόρτωση χρηστών από JSON, με επικύρωση κάθε εγγραφής (ίδιοι κανόνες) και απόρριψη duplicate emails
- [ ] **Σελιδοποίηση**: 10 χρήστες/σελίδα, σωστή σε συνδυασμό με search/filter/sort
- [ ] **Undo delete**: μετά τη διαγραφή μήνυμα με κουμπί «Αναίρεση» για λίγα δευτερόλεπτα, που επαναφέρει τον χρήστη στη θέση του

## Checklist προφορικής (κάν' το 1 μέρα πριν)

- [ ] Μπορώ να εξηγήσω γραμμή-γραμμή τη regex επικύρωσης ονόματος και γιατί αποκλείει τα τόνια
- [ ] Ξέρω τη διαφορά `pattern` (HTML) vs `setCustomValidity` (API) και πότε χρησιμοποιείται το καθένα
- [ ] Ξέρω τι ακριβώς αποθηκεύεται στο `localStorage` (key, format) και πότε γίνεται write
- [ ] Ξέρω γιατί ο `UserStore` είναι υπεύθυνος για όλες τις αλλαγές (single source of truth)
- [ ] Ξέρω τι αλλάζει αν ανοίξω δύο tabs
